# How to Use the GitHub Skills Pitch Deck

This guide explains how to use the pitch deck materials for introducing GitHub Skills as workshop prerequisites.

## Available Formats

### 1. **title-slide.html** (Recommended for Quick Presentations)
- **Best for:** Web-based presentations, quick demos, screen sharing
- **How to use:**
  1. Open `title-slide.html` in any modern web browser
  2. Press `F11` for full-screen mode
  3. Use arrow keys (→ or ←) or spacebar to navigate between slides
  4. Works offline (no internet required after opening)
- **Advantages:** No software needed, looks professional, easy to share
- **Share:** Send the HTML file via email or host on a web server

### 2. **title-slide.md** (Markdown Version)
- **Best for:** Quick reference, editing, converting to other formats
- **How to use:**
  1. Open in any text editor or Markdown viewer
  2. Use for presenting in Markdown-friendly platforms
  3. Easy to copy sections into emails or documents
- **Convert to:** PDF, HTML, or import into presentation tools

### 3. **powerpoint-outline.md** (For Creating PowerPoint)
- **Best for:** Corporate settings requiring .pptx format
- **How to use:**
  1. Open PowerPoint/Keynote/Google Slides
  2. Follow the outline to create slides
  3. Apply GitHub branding (colors, fonts, logos)
  4. Customize for specific audiences
- **Advantages:** Full control over design, animations, and branding

### 4. **flow-diagram.md** (Visual Reference)
- **Best for:** Detailed discussions, understanding the full journey
- **How to use:**
  1. Reference during scoping calls
  2. Use to explain the complete learning path
  3. Share with customers for clarity
- **Include in:** Proposals, scope documents, workshop prep materials

### 5. **quick-reference.md** (Presenter Guide)
- **Best for:** Preparation, handling questions, elevator pitches
- **How to use:**
  1. Review before presenting
  2. Use for practicing your pitch
  3. Reference during Q&A sessions
  4. Customize talking points for your style

## Typical Use Cases

### Scenario 1: Initial Customer Call (15-30 minutes)
**What to use:**
1. Start with elevator pitch from `quick-reference.md`
2. Share screen with `title-slide.html`
3. Walk through the learning journey
4. Reference specific GitHub Skills exercises

**Goal:** Explain the value proposition and get buy-in

### Scenario 2: Formal Presentation (45-60 minutes)
**What to use:**
1. Create PowerPoint using `powerpoint-outline.md`
2. Include customer-specific examples
3. Demo actual GitHub Skills exercises
4. Show `flow-diagram.md` for detailed questions

**Goal:** Complete presentation with Q&A

### Scenario 3: Email Follow-up
**What to use:**
1. Attach `title-slide.html` (self-contained)
2. Include relevant sections from `quick-reference.md`
3. Link to https://learn.github.com/skills
4. Copy flow diagram into email body

**Goal:** Reinforce the concept and provide resources

### Scenario 4: Workshop Introduction (5-10 minutes)
**What to use:**
1. Quick walkthrough of `title-slide.html` (slides 1-3)
2. Emphasize what Skills exercises participants completed
3. Show how workshop builds on that foundation

**Goal:** Set context and expectations

## Customization Tips

### Before Each Presentation

1. **Identify Relevant Skills Exercises**
   - Review available exercises at https://learn.github.com/skills
   - Select 3-5 exercises that align with workshop topics
   - Note them in your presentation materials

2. **Tailor the Message**
   - Reference customer's tech stack
   - Mention their specific challenges
   - Adjust timeline expectations

3. **Prepare Examples**
   - Have 1-2 success stories ready
   - Know typical completion times
   - Be ready to demo an exercise

### Editing the Materials

**To edit title-slide.html:**
- Open in any text editor
- Modify content between HTML tags
- Test in browser after changes
- Keep styling consistent

**To edit Markdown files:**
- Use any text editor (VS Code, Notepad++, etc.)
- Maintain formatting (headers, bullets, code blocks)
- Preview in Markdown viewer before sharing

## Best Practices

### Do's ✓
- Start with customer's pain points
- Emphasize time savings in workshops
- Show the complete learning journey
- Offer to help select relevant exercises
- Follow up with links and resources

### Don'ts ✗
- Don't overwhelm with too many exercises
- Don't skip the "why" (value proposition)
- Don't assume everyone knows GitHub Skills
- Don't rush through the flow diagram
- Don't forget the call to action

## Common Questions & Answers

**Q: "How long does each exercise take?"**
A: Most GitHub Skills exercises take 15-60 minutes. We'll recommend specific ones based on your workshop topics.

**Q: "Do we need GitHub accounts?"**
A: Yes, free GitHub accounts are required. They're free and take minutes to set up.

**Q: "What if some team members can't complete the exercises?"**
A: The exercises are self-paced. We can adjust workshop content if needed, but completing prerequisites ensures everyone gets maximum value.

**Q: "Can we skip the prerequisites?"**
A: While possible, it means workshop time goes to basics instead of advanced, customized content. Prerequisites maximize your ROI.
